# Run report: Fermium 1.5 → 2 → 2.5 (unattended run, ended Sun 2026-09-27 13:00 UTC)

## Where Fermium stands

Fermium is now a single compiled program written in Rust (version 2.5.0). It checks units before your program
runs, understands calculus, and starts in about 15 ms. The run reached **Phase C (v2.5) and its gate**:
- **Phase A:** v1.5 was fixed and frozen.
- **Phase B:** the Rust compiler replaced the Python one. It prints exactly what v1.5 printed on 3324 of 3366
  recorded programs, and the other 42 are documented, deliberate differences.
- **Phase C:** it grew memory management, lists of anything and N-d arrays, events in `solve`, derivatives of
  multi-line functions, unit-checked C, Fortran and C++ calls, multiple dispatch, uncertainties through
  integrals and ODEs, faster loops, and 10 new research reproductions with downloaded data.

Phase D was not started. Five independent red-team rounds (13–17) tested v2.5 during the run; every high finding was
fixed and has a test. The biggest gaps:
- **There is still no download.** GitHub refused every tag push, so you build it once from source (below).
- **The Julia goal is only half met:** of the 6 benchmark programs, faster on 2 (nbody, and forces on both 1
  and 4 threads), level on 1, slower on 3.
- **All of it is in draft pull requests** (#2 → #3 → #4) waiting for your review.

### The unit rule, exactly as the bootcamp states it

From `bootcamp/lesson02_variables_formulas.md`, section "When one of your names is also a unit":

> 1. Right after a number comes a unit: `3 m`, `9.81 m/s²`, `50 N/m`.
> 2. If that unit is a single name that is also one of your variables (`2 g` with your own `g`), Fermium stops and asks which you mean: `2*g` for your variable, `2 [g]` for the unit.
> 3. In a longer unit (`3 m/s`, `2 kg m²`) the first name is always a unit; a later name that is also your variable gets the same question.

The lesson continues: "Anywhere else, a name is your variable, and spaces never change the meaning."
(D235 and CHANGES_1.5 word sentence 3 slightly differently, "a compound unit … is an error that asks the same
question"; the meaning is the same.)

### What you must install today

**The goal was nothing. Today it isn't nothing, because the binaries were never published.**

- **No download exists yet.** `release.yml` builds `fermium-macos-arm64` and `fermium-linux-x86_64`, but only when a
  `v*` tag is pushed, and no tag exists (the pushes were refused; D274).
- **So for now you build from source** (`rust/BUILD.md`). On a Mac: Rust (stable), the Xcode Command Line Tools,
  `brew install llvm@18 lld@18 zstd`, then `make install`. On Linux: `llvm-18-dev`, `lld-18`, `liblld-18-dev` and a
  few more.
- **Once built, the binary needs nothing else.** On Linux, `ldd` shows only libc, libm and libgcc_s; on macOS, only
  `/usr/lib` system libraries. `fermium doctor` reports the version, the built-in LLVM and the platform.
- **Optional features need extra software, only when a program uses them:** `use python` needs libpython;
  `fermium build` on macOS needs the Command Line Tools SDK (never tested on a Mac); `import cpp` (v2.5) needs a C++
  compiler.
- **To publish the binaries:** `git tag -a v2.0 origin/claude/v2.0-freeze -m "Fermium 2.0" && git push origin v2.0`.
  The workflow has never run, so its first run is untested.

## Every divergence from v1.5

`rust/DIVERGENCES.md` has 28 sections. Each entry says what differs, why, and how many conformance programs are
recorded under it (files in `conformance/divergences/`); the counts add up to 42. A count of 0 means no program in
the suite changes; unit tests cover it instead.

1. **The standard library is embedded in the binary.** Imports read a copy built into `fermium`, which is why one
   file is enough. Output is unchanged. *Cases: 0.*
2. **fermium.toml is read by a small TOML reader** (Python's `tomllib` isn't available in Rust). Same simple
   format; only the error text for a broken file differs. *Cases: 0.*
3. **Indefinite integrals: native rules instead of SymPy** (no Python at run time). 43 of 45 textbook integrals
   print exactly as before; some hard ones now stop with "give limits"; `∫ sec x dx` is now right (v1's formula was
   NaN for every real x); logarithms are ln|u|, so answers are real on both sides of a pole. *Cases: 0.*
4. **Display of ∇ results and Leibniz integrands: native tidying.** A smaller simplifier replaces SymPy's. It
   matches every suite program, but some other formulas print in a different, equivalent form. *Cases: 0.*
5. **Quadrature: narrow peaks and half peaks.** v1 could return half the integral, or 0; v2 samples the panel ends
   a second time and gets the true value (spec B2). *Cases: 5.*
6. **Quadrature: strong singularities away from 0.** v1 gave up on `∫ |x − 0.3|^(-0.6) dx`; v2 splits at the
   singular point and extrapolates, about 11 correct digits (B2). *Cases: 2.*
7. **Integrals at the rounding level print only meaningful figures** (`8×10⁻⁹`, not v1's three figures of rounding
   noise); the value itself is identical (B2). *Cases: 14.*
8. **Sums of measured values use the decimal-place rule:** `1.20 m + 2.0 m` prints `3.2 m`, not v1's `3.20 m` (B2,
   D95). Temperatures keep v1's rule. *Cases: 4.*
9. **Special functions and cbrt use the C library, as v1's compiled code did.** Bit-identical on the same
   platform; the last bits can differ between Linux and macOS. *Cases: 0.*
10. **The browser playground (WebAssembly)** replaces Pyodide: no C maths library and a small stack, so very long
    numbers can differ in their last digits, deep recursion stops sooner, and you can't import your own files.
    Playground only. *Cases: 0.*
11. **Implementation differences at the rounding level.** Radau/BDF, fit, eigenvalues, FFT and PDE are ported;
    where not bit for bit, results differ only in the 14th–17th digit. *Cases: 1.*
12. **Plots: native SVG/PNG/GIF instead of matplotlib.** Same style, no Python; not pixel-identical; only
    png/svg/gif. *Cases: 0.*
13. **Lists are freed** (v1's compiled code leaked them, B2). No output changes. *Cases: 0.*
14. **parallel for reports the first failing iteration** (v1's message depended on thread timing). *Cases: 1.*
15. **PDE linear solves: a tridiagonal LU instead of SuperLU** (D268). Results agree to about 14 figures; pure
    rounding noise near zero differs. *Cases: 3.*
16. **PDEs right after a jump: the grid check.** Same values as v1; v2 also re-solves on a half-resolution grid and
    warns when the grid is too coarse (B2). *Cases: 2.*
17. **The command-line tool:** `doctor` checks the one binary; `run --backend`; `--time` shows the back end as one
    number; `fermium build` needs no C compiler (macOS untested); interpreter recursion stops about 500 000 deep
    (v1 went past a million). *Cases: 0.*
18. **The REPL:** its own line editor with `\name` Tab completion; ± works there. *Cases: 0.*
19. **The language server:** rewritten without pygls; same diagnostics, hover, completion and quick fix. *Cases: 0.*
20. **Functions with vector or matrix arguments get a version per shape and units** (v1 crashed). *Cases: 0.*
21. **The Jupyter kernel:** rewritten in Rust, no Python or ZeroMQ; interrupts don't stop a cell yet; warnings show
    after the output. *Cases: 0.*
22. **Python interop:** libpython is loaded only when asked, and must be a shared-library build; `fermium2` has v1's
    API but runs on the interpreter. *Cases: 0.*
23. **v2.5: uncertainties everywhere (C7):** ± in vectors, lists, solve and integrals is computed where v1 stopped
    with "not yet"; each output checked against the analytic derivative. *Cases: 6.*
24. **fermium build safety fixes (red team 13):** programs using Python build; building refuses to overwrite your
    source file (v1 overwrote it); the linker's temporary folder is private. *Cases: 0.*
25. **Unit powers are exact 64-bit fractions:** a power too large to store is a clear error (before the fix it
    wrapped silently or crashed). *Cases: 0.*
26. **v2.5: derivatives of multi-line functions (C2)** by automatic differentiation (D295). *Cases: 2.*
27. **v2.5: conditions on the unknowns in solve are located (C2):** results move within the solver's tolerance,
    towards the more accurate value (0.51019701 M☉ vs v1's 0.51019703; D296). *Cases: 1.*
28. **v2.5: printed derivatives use the tidy form when it is clearly shorter (C2):** `(1 - x²)/(1 + x²)²` instead of
    `(1 + x² - 2x²)/(1 + x²)²`; same values (D298). *Cases: 1.*

The spec-B2 fixes are 5, 6, 7, 8, 13 and 16. The Phase C changes are 23 and 26–28.

## Try it on your Mac

There is no download yet (no release tag could be pushed from here; see "What you must install today"), so you
build it once from source. The first build takes 15–30 minutes, most of it compiling LLVM-linked code.

1. **Tools** (once):
   ```sh
   xcode-select --install                                   # Apple's C/C++ compiler and linker
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh   # Rust; then open a new terminal
   brew install llvm@18 zstd
   brew install lld@18 || true      # optional (for `fermium build`); the formula isn't always available
   ```
2. **Get the v2.5 code:**
   ```sh
   git clone https://github.com/jolive27/fermium.git && cd fermium
   git checkout claude/v2.5
   ```
3. **Build and install** (puts `fermium` in `~/.cargo/bin`, which rustup added to your PATH):
   ```sh
   export LLVM_SYS_180_PREFIX=$(brew --prefix llvm@18)
   export LLD_PREFIX=$(brew --prefix lld@18)
   make install
   ```
4. **Check it:** `fermium --version` should print `fermium 2.5.0 (Rust)`, and `fermium doctor` should say nothing
   else is needed.
5. **Try it:**
   - `fermium run examples/01_pendulum.fm`, then the bootcamp lessons in `bootcamp/` (every code block runs as is).
     Some examples save their plot into `examples/gallery/`, which is part of the repository, so `git status`
     shows it changed afterwards; `git checkout -- examples/gallery` puts it back.
   - Your own programs: `fermium fmt --fix lesson2.fm` once (it adds the two brackets the unit rule asks for),
     then `fermium run lesson2.fm`.
   - New in 2.5: `research/` rows 12–21 (`cd research/cmb_firas && fermium run firas.fm`), multiple dispatch
     and `when` events (`docs/reference.md`), and C++ interop (`cd examples/cpp_interop`, build the library with
     the `c++` line at the top of `cpp_interop.fm`, then `fermium run cpp_interop.fm`).
   - The REPL (`fermium`), with `\omega` + Tab for ω.
6. **If something fails:** `fermium doctor`, and bootcamp Lesson 0's "When something goes wrong". Things never
   run on a real Mac (only on CI's macOS machine): `fermium build` executables, and C++ interop's macOS linking
   (CI covers the second).

Once you push a tag yourself (`git tag -a v2.5 origin/claude/v2.5-freeze -m "Fermium 2.5" && git push origin
v2.5`), the release workflow builds a single downloadable `fermium-macos-arm64`; steps 1–3 are then replaced by
downloading it (Lesson 0 describes that). The workflow has never run, so check its first run.

## Honest weaknesses and next steps

**Weaknesses**
1. **No binary download** (B1, B7). Every tag push was refused, so the release workflow has never run. Building
   from source needs Rust and LLVM 18: 15 minutes and several gigabytes, which is the opposite of the
   "install nothing" goal. *Next:* push the `v2.5` tag yourself (one command above) and check the workflow's first run.
2. **macOS is tested only by CI**, never on a real Mac. `fermium build` executables and C++ interop on macOS
   have never been run by a person.
3. **Performance is uneven** (C6). Fermium is faster than Julia on nbody and forces, but 1.2–2× slower on
   spring_adaptive, spring_rk4 and blackbody. *Next:* batching the integrand for blackbody, and the RK4
   trajectory storage (BACKLOG, "High value").
4. **Parts of v2.5 run in the interpreter.** Programs with ± values, lists of vectors, N-d arrays or list
   unknowns run those parts in the tree-walker (slower), and `fermium build` refuses them.
5. **Open v1 behaviour kept on purpose for parity:** √ or log of a negative number at run time gives NaN
   silently (OPEN_ITEMS A3-NaN); Parseval's sum prints in base SI units (A4-FFT-V2); the interpreter recurses
   about 500 000 deep where v1 went past a million.
6. **Fermium 1.5 (legacy/) keeps bugs v2.5 fixed:** the `fit` error for tiny SI parameters, the (x²)^(3/2)
   derivative, and the formatter turning `fm * A` into a unit. It is frozen as the oracle, so these are listed,
   not fixed.
7. **Messages a beginner still meets without a hint line** (red team 17): the `when` "infinitely many events"
   error, a unit mismatch inside a `when` reset, `A[2, :]` on an array (slices aren't supported), `sin` of an
   array. A text list prints as `[H, He]`, which looks like a unit in brackets.
8. **Research track:** C8's r-process reproduction wasn't done (no downloadable table). The neutron-star cooling
   model assumes a proton fraction of 0.05, flagged in its README.
9. **The run's own environment:** the machine had 15 GB and no swap. Legacy test workers were killed several
   times when agents' test runs overlapped, so some checks were run in two parts (every part passed; stated
   in the commits).
